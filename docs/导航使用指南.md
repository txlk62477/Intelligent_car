# 静态地图导航使用指南

本指南用于在实车上加载已经保存的栅格地图，通过 AMCL 定位，并使用 Nav2
执行目标点导航。建图和导航是两套独立流程；导航时不要启动 Cartographer 或
`slam_nav2.launch.py`。

导航数据链路：

```text
/scan ───────────────> AMCL ─────────────> map -> odom
                         │
/odometry/filtered ──────┴───────────────> odom -> base_link
                                              │
静态地图 -> 全局规划 -> DWB 局部控制 -> /cmd_vel_nav_raw -> 速度平滑 -> /cmd_vel_nav
                                                                           │
      Nav2 /cmd_vel_nav (100)、Motion /cmd_vel_agent (150)、
      遥控 /cmd_vel_teleop (200)、急停锁心跳 /cmd_vel_emergency_lock (255)
                                                                           ▼
                                                                  twist_mux 速度仲裁
                                                                           │
                                                                   /cmd_vel_selected
                                                                           │
                                                                       碰撞监控
                                                                           │
                                                                        /cmd_vel
```

当前实车参数：

- ROS 2 Jazzy，默认使用传感器融合发布的单调 `/clock`。
- 默认地图：包内 `maps/room.yaml`。
- 碰撞监控包络半径：`0.15 m`。
- 最大前进速度：`0.15 m/s`。
- 最大旋转速度：`0.6 rad/s`。
- AMCL 不自动沿用旧位姿，每次启动后都要手动给出初始位姿。

## 1. 安装依赖并构建

首次使用 Nav2 时安装依赖：

```bash
sudo apt update
sudo apt install ros-jazzy-navigation2 ros-jazzy-nav2-bringup
```

构建工作区：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

以后每个新终端都要先加载环境：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

## 2. 启动前安全检查

首次测试应架起驱动轮或把小车放在宽阔、无人的区域，并准备随时断开电机电源。
确保键盘遥控、Agent Gateway 等节点未运行。`navigation2.launch.py` 默认包含统一的
`control_core`，其中 Motion Controller 负责向 twist_mux 发布急停锁心跳；缺少该
心跳时导航会被锁止。

可以检查当前发布者：

```bash
ros2 topic info /cmd_vel -v
```

启动导航前应没有节点直接发布 `/cmd_vel`。导航运行后，最终发布者应为
`collision_monitor`，且 `/cmd_vel_emergency_lock` 应以约 10 Hz 持续更新——这是
Motion Controller 发布的急停锁心跳，心跳停止时 twist_mux 看门狗会锁止全部速度源。

## 3. 启动底盘通信

按项目现有方式启动 micro-ROS Agent：

```bash
sudo docker run --rm -it \
  --name micro-ros-agent \
  --user "$(id -u):$(id -g)" \
  --network host \
  --ipc host \
  -e MICROROS_DISABLE_SHM=0 \
  -e ROS_LOG_DIR=/tmp/ros-log \
  microros/micro-ros-agent:${ROS_DISTRO:-jazzy} \
  udp4 --port 8888 -v6
```

另开终端确认底盘和雷达数据持续更新：

```bash
ros2 topic hz /odom
ros2 topic hz /imu
ros2 topic hz /scan
ros2 topic echo /scan --once --field header
```

`/scan` 的 `frame_id` 应为 `laser_frame`。

## 4. 可选：单独检查车体 TF

另开终端：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_bringup robot_description.launch.py
```

该启动文件只负责发布车体模型和固定变换，包括 `base_link -> laser_frame`。正常启动
导航时不需要单独运行它，因为 `control_core` 已包含相同发布器。不要与
`navigation2.launch.py` 同时启动，也不要启动其他发布 `odom -> base_link` 的旧节点。

## 5. 启动传感器融合和单调时钟

另开终端：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_sensor_fusion fusion.launch.py
```

检查时钟、融合里程计和 TF：

```bash
ros2 topic hz /clock
ros2 topic hz /odometry/filtered
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link laser_frame
```

这四项都正常后再启动 Nav2。融合只能启动一套，否则会产生重复 `/clock`、重复
EKF 和冲突的 `odom -> base_link`。

## 6. 启动静态地图导航

使用包内默认的 `room.yaml`。该命令默认同时启动唯一的 `control_core`（Motion
Controller、twist_mux、碰撞监控、生命周期管理器和车体状态发布器）：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_navigation2 navigation2.launch.py
```

使用自己刚保存的地图时，传入地图 YAML 的绝对路径：

```bash
ros2 launch xuegecar_navigation2 navigation2.launch.py \
  map:=/home/lk/car/data/maps/car_map.yaml
```

无图形界面时关闭 RViz：

```bash
ros2 launch xuegecar_navigation2 navigation2.launch.py \
  map:=/home/lk/car/data/maps/car_map.yaml \
  rviz:=false
```

`navigation2_rviz.launch.py` 仍可作为兼容入口，但推荐统一使用
`navigation2.launch.py`。不要把 `use_sim_time` 改成 `false`，除非底盘、EKF、雷达和
Nav2 全部一起切换到系统时间。

无雷达台架测试可以显式关闭碰撞监控：

```bash
ros2 launch xuegecar_navigation2 navigation2.launch.py \
  use_collision_monitor:=false
```

实车默认保持 `use_collision_monitor:=true`。

需要同时运行 Gateway、导航和 Web GUI 时，使用
`ros2 launch xuegecar_bringup full_control.launch.py`，不要分别以默认参数启动多个
入口；完整入口只创建一次 control core 和 twist_mux。

## 7. 在 RViz 中设置初始位置

Nav2 启动成功后，地图会显示出来，但 AMCL 还不知道小车实际位于地图中的哪里：

1. 在 RViz 顶部点击 `2D Pose Estimate`。
2. 在地图上点击小车的大致实际位置。
3. 按住鼠标拖出箭头，让箭头方向与车头方向大致一致。
4. 松开鼠标，RViz 会向 `/initialpose` 发布初始位姿。
5. 让小车缓慢原地转动或小范围移动，等待粒子云收敛。

不需要点得完全准确，AMCL 会用雷达扫描自动纠偏。开始导航前应满足：

- AMCL 粒子云集中在小车附近，而不是分成多团。
- RViz 中的雷达点与地图墙壁基本重合。
- 小车移动时，地图中的位姿连续、方向正确。

检查完整 TF：

```bash
ros2 run tf2_ros tf2_echo map base_link
```

如果激光点与墙体明显错位，重新使用 `2D Pose Estimate`，不要直接发送导航目标。

## 8. 发送导航目标

定位收敛后，在 RViz 顶部点击 `Nav2 Goal`，再在地图目标位置拖出期望的最终车头
方向。Nav2 将生成全局路径并开始行驶。

首次测试建议：

1. 先发送前方 `0.5~1.0 m` 的近距离目标。
2. 确认小车前进方向、转向方向和 RViz 轨迹一致。
3. 确认前方出现障碍时局部代价地图能标记障碍，碰撞监控能减速或停车。
4. 近距离测试稳定后，再逐渐增加目标距离。

运行状态检查：

```bash
ros2 lifecycle get /map_server
ros2 lifecycle get /amcl
ros2 lifecycle get /controller_server
ros2 lifecycle get /planner_server
ros2 action list | grep navigate
ros2 topic info /cmd_vel -v
ros2 topic hz /cmd_vel_emergency_lock
```

上述生命周期节点应为 `active`，急停锁心跳应约为 10 Hz。导航期间不要同时运行
键盘遥控；Agent Gateway 可以运行（它负责提交导航目标并检测速度源冲突），但直接
通过 RViz 点目标时无需启动它。

## 9. 停止导航

正常停止时，先在 Nav2/RViz 终端按 `Ctrl+C`，确认小车已经停止，再依次停止传感器
融合、车体 TF 和 micro-ROS Agent。

出现运动方向错误、定位跳变或无法避障时：

1. 立即在导航终端按 `Ctrl+C`。
2. 如果小车没有停止，立即断开电机电源或使用硬件急停。
3. 不要在故障状态下继续发送目标进行试错。

## 10. 常见问题

### `ros2` daemon 卡死或显示已经退出的旧节点

`ros2 node list`、`ros2 topic list` 等 CLI 命令默认通过后台 daemon 查询 ROS 图。
daemon 卡死或缓存尚未刷新时，可能出现命令一直不返回、找不到正在运行的节点，或者
仍显示已经退出的旧节点。先确认当前终端加载了正确的 ROS 环境，并保留与运行节点相同
的 `ROS_DOMAIN_ID` 和 `RMW_IMPLEMENTATION`，然后重启 daemon：

```bash
source /opt/ros/jazzy/setup.bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash

ros2 daemon stop
ros2 daemon start
ros2 daemon status
```

重启后重新查询：

```bash
ros2 node list
ros2 topic list
```

如果 `ros2 daemon stop` 本身卡死，先查看 daemon 进程：

```bash
ps -ef | grep '[r]os2-daemon'
```

确认列出的确实是 ROS 2 CLI daemon 后，终止当前用户遗留的 daemon，再启动新实例：

```bash
pkill -f -- '--name ros2-daemon'
ros2 daemon start
ros2 daemon status
```

诊断期间也可以完全绕过 daemon，直接从 DDS 查询当前 ROS 图：

```bash
ros2 node list --no-daemon
ros2 topic list --no-daemon
```

重启 daemon 只会清理 CLI 的 ROS 图缓存，不会停止真正运行的 ROS 节点。若
`--no-daemon` 仍能看到某个“旧节点”，说明该进程实际上还在运行，应先用
`ros2 node info <节点名> --no-daemon` 确认其发布和订阅关系，再回到对应启动终端
正常停止它。不要为了清 daemon 缓存直接删除 `/dev/shm` 内容；这可能破坏正在运行的
Fast DDS 或 micro-ROS 通信。

### 地图加载失败

确认 YAML 和图片文件同时存在，并且 YAML 中的 `image` 路径有效：

```bash
ls -lh /home/lk/car/data/maps/car_map.yaml \
  /home/lk/car/data/maps/car_map.pgm
```

建议让 `image:` 使用相对于 YAML 文件的图片名，例如 `car_map.pgm`。

### RViz 显示 `No map received`

检查地图服务器状态和地图话题：

```bash
ros2 lifecycle get /map_server
ros2 topic echo /map --once --qos-durability transient_local
```

### AMCL 不收敛或激光点错位

依次检查：

```bash
ros2 topic hz /scan
ros2 run tf2_ros tf2_echo base_link laser_frame
ros2 run tf2_ros tf2_echo odom base_link
ros2 topic echo /initialpose --once
```

然后重新设置初始位置并让小车缓慢旋转。如果环境是长直走廊或多个相似房间，应尽量
在特征明显的位置初始化。

### 出现 TF extrapolation 或消息时间过期

检查所有节点是否使用同一个 `/clock`：

```bash
ros2 topic hz /clock
ros2 param get /amcl use_sim_time
ros2 param get /controller_server use_sim_time
ros2 param get /ekf_filter_node use_sim_time
```

三项参数应为 `True`，且只能有一个单调时钟发布者。

### 能规划路径但小车不动

按速度链路逐级检查，定位断点：

```bash
ros2 topic hz /cmd_vel_nav_raw   # 控制器原始输出
ros2 topic hz /cmd_vel_nav       # 速度平滑输出
ros2 topic hz /cmd_vel_selected  # twist_mux 仲裁输出
ros2 topic hz /cmd_vel           # 碰撞监控输出（最终）
```

最常见的断点在 twist_mux 急停锁：它是看门狗语义，`/cmd_vel_emergency_lock`
超过 0.5 秒没有心跳就锁止全部速度源（导航优先级 100 低于锁的 255）。检查：

```bash
ros2 topic info /cmd_vel_emergency_lock -v   # 发布者应为 Motion Controller
ros2 topic hz /cmd_vel_emergency_lock        # 应约为 10 Hz
ros2 topic echo /cmd_vel_emergency_lock --once
```

- 心跳为 `data: true`：有急停或速度源冲突正在锁止；确认安全后提交新任务或调用
  Motion Controller 的 `/motion/set_emergency_lock`（SetBool，`false`）解除。
- 心跳无发布者或频率为零：`control_core` 未运行或 Motion Controller 已退出；
  按第 6 节重新启动 `navigation2.launch.py`。
- 心跳正常但 `/cmd_vel_selected` 无输出：检查 twist_mux 参数与订阅关系。

如果 `/scan` 已停止更新，碰撞监控会阻止速度输出；先恢复雷达数据，不要绕过安全
节点。如果 `/cmd_vel` 正常但底盘不动，再检查 MCU 是否订阅 `/cmd_vel`。

### 小车离墙太近或无法通过窄通道

当前碰撞监控包络半径是 `0.15 m`，膨胀半径是 `0.25 m`。碰撞半径表示不可穿越的实际包络，
膨胀层会让规划器倾向远离墙壁。不要为了通过窄通道直接减小碰撞半径；应先测量真实
车宽、地图比例和定位误差，再调整膨胀层参数。
