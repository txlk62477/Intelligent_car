# 小车启动指南

当前推荐的启动链路如下：

```text
底盘 MCU ──micro-ROS──> /odom、/imu
                            │
                            v
                    Sensor Fusion
                            │
                            v
                    /odometry/filtered

摄像头 ────────────> /camera/image_raw/compressed
                            │
                            v
Agent ──HTTP──> Agent Gateway ──ROS 2 Action──> Motion Controller ──> /cmd_vel
                    │                               ▲
                    └──> Perception Manager ──按需启动 YOLO──┘
```

`gateway.launch.py` 会一起启动 Agent Gateway、独立运动控制节点和
Perception Manager，但不会启动 micro-ROS、传感器融合、摄像头或 Agent。

推荐启动顺序：

1. 启动 micro-ROS Agent。
2. 启动传感器融合。
3. 如果要使用视觉跟随，启动摄像头。
4. 选择键盘遥控，或启动 Agent Gateway 控制栈和智能 Agent。

键盘遥控和 Agent 控制只能二选一。键盘节点也会发布 `/cmd_vel`，不要与
Agent Gateway 控制栈同时运行。

## 0. 构建并加载 ROS 2 工作区

首次运行或代码更新后执行：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

以后每个新的 ROS 2 终端都要先执行：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

## 1. 启动 micro-ROS Agent

这是 UDP 网络通信，不需要挂载 `/dev` 或使用 `--privileged`。启动容器：

```bash
sudo docker run --rm -it \
  --name micro-ros-agent \
  --user "$(id -u):$(id -g)" \
  --network host \
  --ipc host \
  -e MICROROS_DISABLE_SHM=0 \
  -e ROS_LOG_DIR=/tmp/ros-log \
  microros/micro-ros-agent:${ROS_DISTRO:-jazzy} \
  udp4 --port 8888 -v6
```

`--ipc host` 让容器与宿主机共享 IPC。小车的 `/scan` 是包含 360 个距离点的
`LaserScan` 大消息；保留该参数可让 Fast DDS 在条件允许时使用共享内存，避免
容器到宿主机的数据再次经过受 MTU 限制的网络传输。

镜像默认设置 `MICROROS_DISABLE_SHM=1`，因此必须显式覆盖为 `0`。同时通过
`--user "$(id -u):$(id -g)"` 让 Agent 与当前宿主用户使用相同的 UID/GID，避免
Fast DDS 共享内存文件由容器内 `root` 创建后，宿主 ROS 2 节点因权限不同而无法
接收消息。不要写成 `--user lk`：用户名由容器内的 `/etc/passwd` 解析，而镜像中
不一定存在 `lk`；动态读取宿主用户的数字 UID/GID 更可靠。`ROS_LOG_DIR` 指向容器
普通用户可写的 `/tmp/ros-log`。

如果提示容器名 `micro-ros-agent` 已被占用，先确认旧实例：

```bash
sudo docker ps -a --filter name=micro-ros-agent
```

需要重启时执行：

```bash
sudo docker stop micro-ros-agent

sudo docker run --rm -it \
  --name micro-ros-agent \
  --user "$(id -u):$(id -g)" \
  --network host \
  --ipc host \
  -e MICROROS_DISABLE_SHM=0 \
  -e ROS_LOG_DIR=/tmp/ros-log \
  microros/micro-ros-agent:${ROS_DISTRO:-jazzy} \
  udp4 --port 8888 -v6
```

检查启动时间和 IPC 参数是否真正生效：

```bash
sudo docker inspect \
  --format 'User={{.Config.User}} IPC={{.HostConfig.IpcMode}} Started={{.State.StartedAt}}' \
  micro-ros-agent
```

正常应包含当前用户的数字 UID/GID（例如 `User=1000:1000`）和 `IPC=host`。不要
并行启动两个 micro-ROS Agent；两个进程争用 UDP `8888` 会造成底盘会话反复断开。

另开终端检查底盘话题：

```bash
ros2 topic list
ros2 topic hz /odom
ros2 topic hz /imu
```

如果看不到话题，检查主机、容器和底盘 MCU 使用的 `ROS_DOMAIN_ID` 是否一致：

```bash
echo "$ROS_DOMAIN_ID"
docker inspect micro-ros-agent --format '{{range .Config.Env}}{{println .}}{{end}}' | grep ROS_DOMAIN_ID
```

未显式设置 `ROS_DOMAIN_ID` 时默认为 `0`。使用其他 Domain 时，在
`docker run` 中增加 `-e ROS_DOMAIN_ID=<编号>`，宿主机终端也要导出同一个值。

## 2. 启动传感器融合

该启动文件会启动单调 ROS 时间节点和 EKF，输出 `/odometry/filtered`：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_sensor_fusion fusion.launch.py
```

检查融合输出：

```bash
ros2 topic hz /odometry/filtered
ros2 topic echo /odometry/filtered --once
ros2 param get /ekf_filter_node use_sim_time
```

正常情况下，`use_sim_time` 应为 `True`，并且 `/clock`、`/odom`、`/imu`、
`/odometry/filtered` 都在持续更新。

## 3. 启动摄像头（视觉任务必需）

只有在需要视觉理解、目标搜索或视觉跟随时才需要启动：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_camera http_video_publisher.launch.py
```

检查图像话题：

```bash
ros2 topic hz /camera/image_raw/compressed
```

### 使用 rqt 查看图像

另开一个已加载 ROS 2 工作区的终端：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
rqt
```

打开窗口后，在话题下拉框中选择 `/camera/image_raw`。`image_transport` 会通过
`compressed` 插件订阅实际话题 `/camera/image_raw/compressed` 并自动解码。

当前用户的 `~/.bashrc` 已配置：

```bash
alias rqt='rqt --ros-args -p image_transport:=compressed'
```

因此直接运行 `rqt` 就会默认使用压缩传输。修改配置后，已有终端需要先执行
`source ~/.bashrc`，新终端会自动生效。

当前摄像头配置默认发布压缩图像，并且不发布占用带宽更高的原始图像：

```yaml
topic: "/camera/image_raw/compressed"
raw_topic: "/camera/image_raw"
publish_raw: false
```

`compressed` 是 ROS 参数和图像传输插件名称，不需要也不建议设置成环境变量。
本机已经安装 `compressed_image_transport`。如果换到没有安装该插件的机器，可执行：

```bash
sudo apt install ros-jazzy-compressed-image-transport ros-jazzy-rqt-image-view
```

如果摄像头地址发生变化，修改：
```text
/home/lk/car/software/leap_ros_ws/src/xuegecar_camera/config/http_video_publisher.yaml
```

## 4. 控制方式二选一

### 4.1 键盘遥控

只需要手动控制时运行：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

此时不要启动下面的 Agent Gateway 控制栈。

### 4.2 智能 Agent 控制

#### 终端 A：启动 Gateway 控制栈

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch xuegecar_agent_bridge gateway.launch.py
```

该命令会启动：

- `Agent Gateway`：接收 Agent 的 HTTP 请求，提交 ROS 2 Action，并汇总状态。
- `Motion Controller`：独占 `/cmd_vel`，执行位置移动和视觉跟随。
- `Perception Manager`：按任务需要启动和关闭 YOLO。

视觉跟随期间，运动控制节点根据识别框位置控制左右转向，并以首次稳定识别框
的面积作为距离基准控制前进和后退。当前没有使用雷达避障，只能在有人看护的
安全区域内测试。

检查控制栈：

```bash
ros2 action list
ros2 service list | grep perception
curl -sS http://127.0.0.1:8765/v1/robot/status | python3 -m json.tool
curl -sS http://127.0.0.1:8765/v1/camera/snapshot | python3 -m json.tool
curl -sS http://127.0.0.1:8765/v1/perception/detections | python3 -m json.tool
```

`/v1/camera/snapshot` 会抓取相机最新帧并保存到 `/home/lk/car/data/snapshots/`；
`/v1/perception/detections` 返回当前画面的 YOLO 检测列表（类别、置信度、画面位置），
检测数据过期时会临时拉起 YOLO（默认 20 秒短租约）等待新鲜结果。未收到相机帧时两个
接口分别返回 `NO_FRAME`。

空闲时 YOLO 不会运行。可以这样确认：

```bash
ros2 node list | grep yolo
```

没有输出是正常现象。Agent 发出视觉跟随任务后，Perception Manager 才会启动
YOLO；任务成功、失败、取消或超时后会自动关闭 YOLO。

YOLO 使用的软件包内虚拟环境位于
`/home/lk/car/software/leap_ros_ws/src/xuegecar_perception/.venv`，启动时会由
`perception.launch.py` 自动加载，不需要在终端手动激活。

#### 终端 B：启动智能 Agent

```bash
cd /home/lk/car/agents/car_agent
source .venv/bin/activate
langgraph dev --no-browser
```

Agent 默认访问：

```text
http://127.0.0.1:8765
```

启动后可以下达“前进 0.5 米”“左转 90 度”“寻找并跟随水杯”等高层任务，
也可以询问“看看当前画面里有什么”（不给图片路径时，Agent 会自动抓取
相机当前帧交给视觉模型识别）。要求跟随某物体时，Agent 会先读取当前
YOLO 检测列表：目标存在则确认后开始跟随；目标不存在会把检测到的候选
物体列出来让你选择序号。Agent 只负责下达任务；Gateway 和运动控制节点
负责持续执行、反馈、取消和超时。

同一时间只允许一个运动任务。小车忙碌时，新任务会返回 `busy`，急停请求除外。
任务总超时默认 60 秒，可由请求设置，最大 300 秒；视觉搜索连续 10 秒没有找到
目标时，任务会失败并停车。

## 5. 状态检查与急停

查看小车和当前任务的汇总状态：

```bash
curl -sS http://127.0.0.1:8765/v1/robot/status | python3 -m json.tool
```

视觉跟随状态含义：

- `STARTING`：正在启动视觉检测。
- `SEARCHING`：正在搜索目标。
- `TRACKING`：已找到目标，正在跟随并调整位置。
- `ALIGNED`：目标已位于画面中心，并且识别框大小处于目标范围。

遇到异常时可从任意终端执行急停：

```bash
curl -sS -X POST \
  -H 'Content-Type: application/json' \
  -d '{}' \
  http://127.0.0.1:8765/v1/stop
```

急停会取消当前任务并发布零速度，但仍应确保物理急停开关可用。

## 6. 可选：录制传感器数据

需要排查里程计或 IMU 时，可以录制：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 bag record --use-sim-time \
  /clock /odom /imu \
  /fusion/odom_valid /fusion/imu_valid \
  /odometry/filtered /diagnostics /tf /tf_static
```

录制完成后按 `Ctrl+C` 停止。

## 7. 停止顺序

在各自终端按 `Ctrl+C`，推荐顺序为：

1. 智能 Agent。
2. Agent Gateway 控制栈。
3. 摄像头节点。
4. 传感器融合节点。
5. micro-ROS Agent 容器。

micro-ROS Agent 使用了 `docker run --rm -it`，在其终端按 `Ctrl+C` 后容器会
自动删除。
