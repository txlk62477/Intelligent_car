# 小车启动指南

本文档是小车的统一启动入口。

## 启动架构

```text
底盘 MCU ──micro-ROS──> /odom、/imu、/scan
                              │
                              v
                      Sensor Fusion
                              │
                              ├──> /odometry/filtered
                              └──> /scan_ts

摄像头 ──> /camera/image_raw/compressed

Agent ──HTTP──> Agent Gateway ──ROS 2 Action──> Motion Controller ──> /cmd_vel_agent
                    │                               ▲
                    └──> Perception Manager ──按需启动 YOLO──┘
Web GUI ──> /cmd_vel_teleop
Nav2 ─────> /cmd_vel_nav
                    │
                    v
       twist_mux → collision_monitor → /cmd_vel → 底盘
```

`full_control.launch.py` 是全功能的统一 ROS 2 入口，会启动：

- 唯一的 `control_core`、`twist_mux` 和碰撞监控（`xuegecar_bringup` 包的 `collision_monitor`）
- Agent Gateway 和 Perception Manager
- Navigation2、AMCL 和 RViz
- Web GUI

它不会启动 micro-ROS Agent、传感器融合、摄像头或 LangGraph Agent
Server，这四项需要在独立终端启动。

Navigation2、Agent 和 Web GUI 可以同时运行，速度指令由 `twist_mux` 统一仲裁。
Web GUI 手动控制优先级最高，会暂时抢占 Agent 或导航的控制权。全功能模式下
不要运行默认直接发布 `/cmd_vel` 的 `teleop_twist_keyboard`，它会绕过速度仲裁和
碰撞监控。

## 首次构建

首次运行或代码更新后执行：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

日常启动时不需要再进入工作区，每个 ROS 2 终端只需执行：

```bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash
```

## 全功能启动

打开 5 个终端，按以下顺序启动。

### 终端 1：底盘 micro-ROS Agent

```bash
sudo docker run --rm -it \
  --name micro-ros-agent \
  --user "$(id -u):$(id -g)" \
  --network host \
  --ipc host \
  -e MICROROS_DISABLE_SHM=0 \
  -e ROS_LOG_DIR=/tmp/ros-log \
  microros/micro-ros-agent:${ROS_DISTRO:-jazzy} \
  udp4 --port 8888 -v6
```

不要并行启动多个 micro-ROS Agent，否则会争用 UDP `8888` 端口。

### 终端 2：传感器融合与统一时钟

```bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash
ros2 launch xuegecar_sensor_fusion fusion.launch.py
```

### 终端 3：摄像头

```bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash
ros2 launch xuegecar_camera http_video_publisher.launch.py
```

### 终端 4：导航、Gateway、Web GUI 和控制链

```bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash
ros2 launch xuegecar_bringup full_control.launch.py
```

默认地图为：

```text
/home/lk/car/data/maps/room_map.yaml
```

默认同时启动 RViz 并启用碰撞监控。临时使用其他地图时：

```bash
ros2 launch xuegecar_bringup full_control.launch.py \
  map:=/home/lk/car/data/maps/car_map.yaml
```

`full_control.launch.py` 已经包含 `navigation2.launch.py`、`gateway.launch.py` 和
Web GUI。不要再另开终端重复启动这些 launch，否则可能出现重复节点、端口占用
或多个 `twist_mux`。

### 终端 5：LangGraph 智能 Agent

```bash
cd /home/lk/car/agents/car_agent
source .venv/bin/activate
langgraph dev --no-browser
```

启动后可访问：

- LangGraph Agent Server：`http://127.0.0.1:2024`
- Agent API 文档：`http://127.0.0.1:2024/docs`
- Robot Gateway：`http://127.0.0.1:8765`
- Web GUI：`http://127.0.0.1:8000`
- 手机 Web GUI：`http://<主机局域网IP>:8000`

## 碰撞监控与 2 cm 虚拟实体

控制链里的碰撞监控来自 `xuegecar_bringup` 包的 `collision_monitor` 可执行文件，
不再是 `nav2_collision_monitor` 的原版可执行文件。它沿用 Nav2 的 TF、激光转换和
碰撞时间（TTC）流程，只额外增加“已停稳后可低速直线退避”这一层例外。构建
`xuegecar_bringup` 时才会生成该可执行文件，改动控制逻辑或参数后必须重新构建并
重启控制栈：

```bash
cd /home/lk/car/software/leap_ros_ws
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select xuegecar_bringup
source install/setup.bash
```

车身实测轮廓为 `x` 方向 0.124～-0.0325 m、`y` 方向 ±0.0725 m。保护分三层：

| 层 | 覆盖范围 | 行为 |
|---|---|---|
| 提前减速 | 2 cm 保护区外约“速度 × 1 s”（0.15 m/s 约 15 cm，0.3 m/s 约 30 cm） | `FootprintApproach` 按 1.0 s 碰撞时间限速，先减速再接近 |
| 2 cm 硬保护区 | 车身四周外扩 2 cm（`x` 0.144～-0.0525，`y` ±0.0925） | 区内出现 ≥3 个障碍点立即停车，继续前进和转向都被拦截 |
| 低速退避例外 | 同上 | 仅当“已停稳 + 纯直线速度指令 + 障碍只压住车头或车尾 5 mm 以内 + 另一侧与侧面干净”时生效，允许最大 0.03 m/s 直线远离障碍 |

任何一项不满足都继续停车：正在旋转或边退边转、两侧同时有障碍、障碍点已深入
车身 5 mm 以上、后退方向上还有别的障碍，或者 `/scan_ts`、TF、里程计超时。
退避不会自动发生，需要有人（或 Agent）持续下发直线速度指令；指令停止 0.3 s 后
监控节点主动归零。

参数文件：`software/leap_ros_ws/src/xuegecar_bringup/config/collision_monitor.yaml`

| 参数 | 默认值 | 作用 |
|---|---|---|
| `FootprintApproach.time_before_collision` | 1.0 | 提前减速的预测时间，速度越大预测距离越远 |
| `FootprintApproach.simulation_time_step` | 0.01 | 预测步长 |
| `VirtualStop.min_points` | 3 | 触发停车的最少障碍点数 |
| `hard_stop_padding` | 0.02 | 车身外扩的 2 cm 虚拟实体厚度 |
| `escape_max_speed` | 0.03 | 退避时的最大线速度，只做直线 |
| `escape_body_overlap` | 0.005 | 允许退避的最大浅重叠深度 |
| `escape_stopped_linear` / `escape_stopped_angular` | 0.04 / 0.05 | 判定“已停稳”的里程计阈值 |
| `command_timeout` | 0.3 | 速度指令超时后主动归零的秒数 |
| `source_timeout` | 1.0 | 激光数据失效后停车 |

检查命令：

```bash
ros2 lifecycle get /collision_monitor
ros2 param get /collision_monitor FootprintApproach.time_before_collision
ros2 param get /collision_monitor hard_stop_padding
ros2 param get /collision_monitor escape_max_speed
ros2 topic echo /collision_monitor_state
```

RViz 中可以添加 `/virtual_stop_polygon`（2 cm 硬保护区）和
`/footprint_approach_polygon`（提前减速区）两个 `PolygonStamped` 显示，用于确认
保护区方向和范围符合预期。

## 启动后设置导航初始位姿

AMCL 每次启动后都不知道小车在地图中的实际位置。发送任何导航任务前：

1. 在 RViz 中点击 `2D Pose Estimate`。
2. 在地图上点击小车的实际位置，拖动箭头指向车头方向。
3. 等待粒子云收敛，并确认雷达点与地图墙体基本重合。

## 状态检查

确认以下项目正常后再让小车运动：

```bash
source /home/lk/car/software/leap_ros_ws/install/setup.bash
ros2 topic hz /clock
ros2 topic hz /odometry/filtered
ros2 topic hz /scan_ts
ros2 lifecycle get /collision_monitor
ros2 lifecycle get /amcl
ros2 lifecycle get /controller_server
curl -sS http://127.0.0.1:8765/v1/robot/status | python3 -m json.tool
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8000/
```

`/clock`、`/odometry/filtered` 和 `/scan_ts` 应持续更新；`collision_monitor`、AMCL 和
Nav2 生命周期节点应为 `active`；两个 HTTP 检查应成功。

遇到异常时可执行急停：

```bash
curl -sS -X POST \
  -H 'Content-Type: application/json' \
  -d '{}' \
  http://127.0.0.1:8765/v1/stop
```

软件急停不能代替物理急停开关。

## 停止顺序

在各自终端按 `Ctrl+C`，推荐顺序为：

1. LangGraph 智能 Agent。
2. `full_control.launch.py`。
3. 摄像头节点。
4. 传感器融合节点。
5. micro-ROS Agent 容器。

`full_control.launch.py` 停止时会一并停止导航、Gateway、Web GUI 和共享控制链。
micro-ROS Agent 使用 `docker run --rm -it` 启动，在对应终端按 `Ctrl+C` 后容器会
自动删除。
